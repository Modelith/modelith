# ADR-0004: プラグインの構成と段階的導入

- 状態: 採用
- 日付: 2026-10-07

## 背景

サードパーティを含むエコシステムを目指す。検査ルールのようなプラグインがブラウザでしか動かないと、
CI で同じ検査ができず、ADR-0002 で避けた「ブラウザでは通るのに CI で落ちる」問題が再発する。

## 決定

### 段階

| 段階 | 種類 | 動く場所 | 主な用途 |
| --- | --- | --- | --- |
| v0 | YAML 宣言ルール（コアが解釈） | ブラウザ・CLI・CI・サーバすべて | 検査ルール。システムズエンジニアが自分で書ける |
| v1 | TypeScript（ESM ＋ Web Worker） | ブラウザ | インポータ・エクスポータ・ビュー・パレット・コマンド |
| v2 | WASM Component（WIT） | ブラウザ（jco）・CLI/サーバ（wasmtime） | ヘッドレスでも動かしたいプラグイン |

### 境界と契約

- プラグインとの契約（マニフェスト・メッセージ・`TextEdit` 等の型、JSON Schema、将来の WIT）は
  **`modelith/plugin-sdk`（MIT）に 1 箇所で定義**し、TypeScript 型・JSON Schema は生成物とする。
  本リポジトリはホスト側の実装（AGPL）だけを持ち、契約は plugin-sdk に依存する。
- プラグイン API のバージョンは plugin-sdk の semver に一致させる。マニフェストの `apiVersion` で対応範囲を宣言する。
- プラグインは DOM に触れない。モデルを読み、`TextEdit` の変更案を返すだけで、適用前にコアが検証する。
- 権限（モデル読み取り・変更案・ネットワーク・ストレージ）をマニフェストで宣言させ、ホストが強制する。
- ビュー追加は当面、宣言的な描画指定（JSON）を返す方式とし、任意 JS の UI はサンドボックス化した iframe を用意してから開放する。

### リポジトリの役割

| リポジトリ | ライセンス | 役割 |
| --- | --- | --- |
| `plugin-sdk` | MIT | 契約の定義（Rust 型 → TS 型・JSON Schema 生成）、TS 用ヘルパー、将来の WIT |
| `plugin-template` | MIT | TS 版と YAML ルール版のひな形 |
| `plugins` | MIT | 公式無料プラグインのモノレポ |
| `plugins-pro` | 非公開 | 有料プラグイン。価値はサーバ側に置く。ホストとはプラグイン API／プロセス境界越しにだけ接続する（ADR-0006） |
| `plugin-registry` | — | 索引（1 プラグイン 1 JSON）と、それを静的に検証する TS の CI。プラグイン実体は置かない |

### レジストリの安全原則

- PR の CI で投稿されたプラグインのコードを実行しない。スキーマ検証・ID 衝突・ハッシュと署名の照合・
  `apiVersion` 範囲・宣言権限と使用 API の静的な突き合わせ・ライセンス表記の確認までに留める。
- 第三者が PR で登録できるよう、`plugin-registry` は public にする。

## 結果

- v0 の時点で「組織ごとの検査ルールを CI でも同じ結果で回す」ことが実現できる。
- plugin-sdk の破壊的変更はエコシステム全体を壊すため、メジャーバージョンでのみ行い、ADR を追加する。
