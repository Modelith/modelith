# ADR-0014: 画面の言葉は、SysML v2 の構文を知らない人に合わせる

- 状態: 採用
- 日付: 2026-10-14

## 背景

これまでの画面の文言には、SysML v2 の構文やキーワードがそのまま出ていた。

- 「`satisfy B by A` を追加しました」「`part e : Engine` を追加しました」
- 「view の expose に、部品を持つ part def がありません」
- 「package の中身を出すときは `expose P::*;` のように書きます」

利用者の多くは、SysML v2 の仕様を覚えていない。図で整理していきたいという要求が強く、テキストの書き方を案内されても戸惑い、使わなくなってしまう。
一方で、テキストが唯一の正本であり（ADR-0001）、テキストを書く利用者や、他の SysML v2 ツールと行き来する利用者もいる。

## 決定

**画面の言葉は、図の上で起きたことと、次に画面で何をすればよいかで書く。SysML v2 の用語は、必要なときだけ補足として添える。**

- 主語は図の言葉にする。「部品」「要求」「満たす」「検証する」「流れ」「保存された図」など。
- 次の操作は、画面の操作で示す。「上のパレットの『シナリオ』から作れます」のように書く。テキストの書き方を、操作の手順として求めない。
- SysML v2 のキーワード（`part def`・`satisfy`・`expose` など）は、括弧の補足かツールチップに回す。テキストを書く人が、テキストと結び付けられるようにするため。
- テキストの行を指す問題一覧だけは、どの書き方が原因かを補足に書いてよい。ただし先頭は意味で書く（「『満たす』関係の相手『X』が見つかりません（satisfy）」）。
- 図に描く記号（`«part def»` などのステレオタイプ）は、SysML v2 のグラフィカル記法そのものなので、そのまま使う。
- 書き方の細則は [画面の言葉の手引き](../development/ui-writing.md) に置く。

## 結果

- SysML v2 を知らない利用者も、図の操作だけで迷わず使える。
- テキストを書く利用者は、補足からテキストの書き方をたどれる。
- 文言はモックに合わせない。ゴールデン（ADR-0002）は、問題一覧のどこに・どの種類の問題を出すかを比べ、文言は比べない。
- 新しい文言を足すときは、手引きに照らしてレビューする。同じ種類の逸脱が続いたら、機械的な検査を足す（ADR-0008）。
