# ADR-0020: 安定版とプレリリース版を、別の URL で同時に公開する

- 状態: 採用
- 日付: 2026-10-22

## 背景

Web アプリは GitHub Pages（`https://modelith.github.io/modelith/`）で公開している。
これまでの公開のワークフロー（`.github/workflows/pages.yml`）は、リリースを公開するたびに、その版でサイトを丸ごと置き換えていた。
0.1.0 の間は版が 1 本だったので困らなかったが、`0.1.0-rc.1`（正式版の候補）を出したあと、`0.2.0` の alpha を出し始めると次のことが起きる。

- alpha を公開した時点で、rc を使っている人の画面が、開発中の alpha に置き換わる
- 試したい人が alpha・beta を使い、ふだん使いの人が安定した版を使う、という分け方ができない

GitHub Pages は 1 つのリポジトリにつき 1 つのサイトしか置けない。
また、同じオリジン（`modelith.github.io`）に置いた 2 つの版は、ブラウザの保存領域（localStorage・IndexedDB）を共有する。
新しい版が書いた形式（前回の続き・下書き・設定・許可したプラグイン・フォルダの許可）を古い版が読むと、壊れたり、知らない値で止まったりするおそれがある。

## 決定

### 1. 系列と URL

| 系列 | URL | 置く版 |
| --- | --- | --- |
| 安定版（stable） | `/modelith/` | 最新の正式版。正式版がまだ無ければ、最新の rc |
| プレリリース版（preview） | `/modelith/preview/` | 段階（alpha・beta・rc・正式版）によらず、最も新しい版 |

- 版の前後は SemVer の順（同じ版の中は alpha < beta < rc < 正式版。番号は数として比べる）。
- 下書きと、`v<MAJOR>.<MINOR>.<PATCH>[-(alpha|beta|rc).<N>]` の形でないタグは選ばない。
- 最も新しい版が正式版なら、プレリリース版の URL も同じ版になる。

### 2. 公開のしかた

- どのリリースを公開しても、公開済みのリリースの一覧から 2 つの版を選び直し（`web/tools/channels.ts`）、両方をビルドして 1 つのサイトにまとめる（`scripts/pages-build.sh`）。
- 版ごとに、そのタグの中身で e2e・UI テストを流してからビルドし、テストのレポートもその版の `reports/` に置く。どちらかが失敗したら公開しない。
- リリースの公開で動くワークフローは、そのタグのコミットにある `pages.yml` を使う。このため、この仕組みを含まないコミットに付けた下書き（この ADR より前に作った下書き）は、公開すると以前の動き（サイトの丸ごとの置き換え）になる。
  そうした下書きは公開せず、この仕組みを含むコミットで下書きを作り直す。
- 手で公開し直すときは、`pages.yml` を既定のブランチから手動で起動する（`workflow_dispatch`）。

### 3. 保存領域を系列ごとに分ける

- ビルドの系列を `MODELITH_CHANNEL`（`stable`・`preview`。既定は `stable`）で渡し、アプリに `__APP_CHANNEL__` として埋め込む。
- localStorage のキーと IndexedDB のデータベース名は、プレリリース版では後ろに `@preview` を付ける（`web/src/channel.ts`）。安定版は名前を変えず、それまでの保存を引き継ぐ。
- このため、プレリリース版を初めて開くと、前回の続き・下書き・設定・プラグインの許可・フォルダの許可は空から始まる。ファイルそのものは同じものを開ける。

## 結果

- alpha・beta を公開しても、安定版の URL の人の画面は変わらない。
- 1 回の公開で 2 つの版をテストしてビルドするので、公開にかかる時間はおよそ 2 倍になる。
- 2 つの系列の間で、下書きや設定は引き継がれない。プレリリース版で試した内容を安定版に持ち込むには、ファイルに保存する。
- マニュアル（modelith.github.io）と README は、安定版の URL を案内し、プレリリース版の URL を「試したい人向け」に添える。
