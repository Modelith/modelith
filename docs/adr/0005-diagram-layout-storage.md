# ADR-0005: 図の中身は標準の view で表し、配置はモデルごとの別ファイルに保存する

- 状態: 採用（2026-10-13 改訂）
- 日付: 2026-10-07

## 背景

モックは配置情報をテキスト内の `/* @layout {...} */` コメントに、図のタブを localStorage に保存している。この方式には次の問題がある。

- 図を操作すると、利用者の SysML ファイルに大きなコメントが勝手に書き込まれる。
- 座標の変更が、モデルの差分に混ざる。
- 人と AI エージェントが同じファイルを編集すると、コメントが壊されたり、競合したりしやすい。

一方、SysML v2 には図の中身を表す標準がある。

- `view` / `view def`（`expose`・`filter`・`render`）
- 標準ライブラリ `Views`（`asTreeDiagram`・`asInterconnectionDiagram` など）
- 標準ライブラリ `StandardViewDefinitions`（`GeneralView`・`InterconnectionView`・`StateTransitionView`・`SequenceView`・`BrowserView` など）

ただし、要素の位置や線の経路は標準の範囲外である。

## 決定

**標準でできることは標準で表し、標準で足りないところだけを Modelith 独自の仕組みで補う。**

| 情報 | 保存先 | 根拠 |
| --- | --- | --- |
| どの図に、どの要素を出すか | テキスト内の標準の `view`（`expose`・`filter`） | SysML v2 標準。他のツールやエージェントも読める |
| どの図の種類で描くか | `view` の定義（`StandardViewDefinitions`）と `render` | SysML v2 標準。足りない描き方は Modelith の既定で補う |
| 座標・接続点・線の端 | モデルごとの隣のファイル（`model.sysml` → `model.layout.json`） | 標準の範囲外なので独自に持つ |

### view
- テキストに書かれた `view` を、図（タブ）として表示する。`expose` された要素だけを描く。
- 図の種類は、`view` が型付けされた標準のビュー定義から決める。

  | 標準のビュー定義 | Modelith の描き方 |
  | --- | --- |
  | `GeneralView` | ノードと線の図（トレーサビリティ・構造など） |
  | `InterconnectionView` | 内部ブロック図 |
  | `StateTransitionView` | 振る舞い（状態遷移） |
  | `SequenceView` | シーケンス図 |

- `expose P`（package そのもの）は、仕様どおり package だけを出す。package を枠として描く仕組みができるまでは、図が空になるので、その理由と中身を出す方法を示す。
  package を枠（フォルダ形）として描き、中の要素を枠の中に示す描き方は、[リリース計画](../development/release-plan.md) の alpha.4 で入れる（F-VIEW-9）。
  `expose P` を `P::*` と同じに扱う読み替えはしない（他のツールで開いたときに図が変わるため）。
- 画面から図を作ったときだけ、`view` をテキストに書く。利用者が操作したときにだけ書き込み、勝手には書かない。
- 今の 7 種類のビューは、`view` が無くても見られる「自動の図」として残す。標準の図を補う Modelith の便利機能という位置づけ。
- 開いているタブの記録は、モデルではなく画面の状態なので、これまでどおりブラウザに置く。

### 画面から図を作る（F-VIEW-8）

利用者には `view`・`expose` という言葉を見せない。「図を保存する」「図に入れる」「図から外す」という操作にし、裏で標準の `view` を書く（ADR-0014）。

| 操作 | 画面 | テキスト |
| --- | --- | --- |
| 図を保存する | 自動の図で「図を保存」を押し、名前を付ける。見えている要素のまま「保存された図」に加わり、そのタブが開く | 最初の package の末尾に `view 名前 : 標準のビュー定義 { expose …; }` を書く。要素は 1 つずつ `expose` する。配置もそのまま引き継ぐ |
| 図に入れる | 保存された図で、パレットから新しい要素を置く。またはツリーから要素をドラッグする | 要素を作り（パレットのとき）、`expose` の行を足す |
| 図から外す | 右クリックの「この図から外す」 | その要素だけを出している `expose` の行を消す。モデルの要素は残す |
| モデルから削除 | 右クリックの「モデルから削除」 | これまでどおり要素の宣言を消す |

- 図の種類は、元の自動の図から決める。トレーサビリティ・構造・制御ループ・すべては GeneralView、振る舞いは StateTransitionView、内部ブロック図は InterconnectionView（対象のブロックを `expose`）、シーケンスは SequenceView（対象のシナリオを `expose`）。
- 名前は日本語でもよい。SysML の名前に使えない文字を含むときは、引用名（`'…'`）で書く。
- 「P の中身すべて」（`expose P::*`）のようにまとめて出している要素は、1 つだけ外せない。そのことを伝え、テキストで直すときの手掛かりを補足に書く。
- 「図から外す」と「モデルから削除」は、取り違えてモデルを消さないよう、別の操作として並べる。

### 配置ファイル
- **テキスト（`.sysml`）には配置を一切書かない。** モデルのテキストは純粋な SysML のままにする。
- 配置ファイルはモデルごとに 1 つ置く（フォルダに 1 つではない）。別のファイルを編集しても、配置ファイルは競合しない。
- 書き出し方
  - キーは要素の修飾名にする
  - キー順を固定し、要素ごとに 1 行で書く（差分とマージを読みやすくするため）
- 名前の変更
  - Modelith の中で名前を変えたときは、テキストと配置ファイルを同時に更新する
  - 他のツールやエージェントが名前を変えたときは、その要素の位置を引き継げず、自動で配置し直す。古い配置は残すが、使わない
- 保存先は利用者に決めてもらい、配置が保存されていない状態を必ず画面に示す（draw.io と同じ考え方）。

  | 開き方 | 動き |
  | --- | --- |
  | フォルダを開いている | 隣の `.layout.json` を、何も聞かずに読み書きする |
  | 新しいファイルを保存する（Chrome・Edge） | 保存先のフォルダとファイル名を選んでもらい、`.sysml` と `.layout.json` を一緒に作る |
  | ファイルを 1 つだけ開いた（Chrome・Edge） | 配置を変えると「配置は未保存」と示す。保存のときに、そのファイルのフォルダを開くよう尋ねる |
  | Safari・Firefox | 保存のとき `.sysml` と `.layout.json` を両方ダウンロードする。開くときに 2 つを一緒に選べば、配置も戻る |

- 移行：既存の `@layout` コメントは、読み込みに使う。配置ファイルに移してテキストからコメントを消すかは、利用者に一度だけ尋ねる。黙って消さない。

## 実装の順序

1. 配置ファイルの分離（テキストに書かない・保存先を決めてもらう・移行）
2. テキストの `view` を読んで図として表示する（パーサに `view`・`expose`・`filter`・`render` を足し、ゴールデンのケースを追加する。ADR-0002）
3. 画面から `view` を作る

## 結果

- 利用者の SysML ファイルに、Modelith が勝手に何かを書き込むことはなくなる。
- 図の中身は標準の `view` なので、他の SysML v2 ツールやエージェントとそのまま共有できる。
- モデルの差分レビューから、座標の変更が消える。
- 1 つのモデルが「テキストと配置」の 2 ファイルになり、ファイル操作（保存・名前変更・ダウンロード）は 2 つを組で扱う必要がある。
