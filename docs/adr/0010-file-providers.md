# ADR-0010: ファイル操作をストレージごとのプロバイダに分け、ワークスペースが束ねる

- 状態: 採用
- 日付: 2026-10-12

## 背景

利用者は VS Code のように、手元のフォルダを開いてファイルを編集・上書き保存したい（N-3）。
将来は Google ドライブなどのクラウドのファイルも同じ操作で扱いたい（F-FILE-12）。
ストレージごとに、できること（フォルダの一覧・上書き・競合の検出）も、識別子の形（パスか ID か）も違う。
ブラウザによっては、ローカルのフォルダを開く API（File System Access API）自体が無い。

## 決定

- **ファイルの参照は不透明な `FileRef`**（`provider`・`id`・表示名・表示用のパス）とし、パスを前提にしない。
- **ストレージごとにプロバイダを作る。** プロバイダは、できることごとに分けた小さなインタフェースを実装する（インタフェース分離）。

  | インタフェース | できること |
  | --- | --- |
  | `Readable` | ファイルを読む（本文と版） |
  | `Writable` | 版を指定して上書きする。版が変わっていれば `ConflictError` |
  | `FolderSource` | フォルダを選ぶ・一覧する・ファイルを作る |
  | `FilePicker` | ファイルを 1 つ選ぶ |
  | `SaveAsTarget` | 保存先を選んで保存する |

  UI は「このプロバイダは `Writable` か」で振る舞いを切り替え、未対応の操作を呼んで例外にすることはしない。
- **版（version）は不透明な文字列**で、プロバイダが決める（ローカルは更新日時と大きさ、ドライブは revision など）。
  上書きの前に版を比べ、他で変わっていれば利用者に選ばせる（F-FILE-7）。
- **ワークスペース**が、開いているファイル（文書）・未保存の変更・保存・競合・外部での変更の読み直しを受け持つ。
  ワークスペースはプロバイダのインタフェースにだけ依存し、DOM やブラウザの API を知らない（依存性逆転）。
  自動保存・下書きの保存先・時刻は外から渡し、単体テストではメモリ上のプロバイダとタイマーに差し替える。
- 最初に作るプロバイダ
  - `LocalFolderProvider`：File System Access API（Chrome・Edge）。前回のフォルダは IndexedDB に覚え、許可を得て開き直す
  - `BrowserFileProvider`：ファイルの読み込みとダウンロードだけを使う代替（Safari・Firefox）
- クラウドは後から `CloudProvider`（例: Google ドライブ）を足すだけで済む形にする。
  認証（OAuth）はプロバイダの中に閉じ、ワークスペースと UI は変えない。

## 結果

- ストレージを足しても、ワークスペースと UI を書き換えずに済む（開放閉鎖）。
- ファイルを扱う判断（保存・競合・自動保存）を、ブラウザなしで単体テストできる。
- File System Access API の無いブラウザでは、上書き保存の代わりにダウンロードになる。
