# ADR-0013: モックと SysML v2 仕様が食い違うときは仕様に従う

- 状態: 採用
- 日付: 2026-10-14

## 背景

ADR-0002 は「仕様の基準はモック」とし、暫定コア（ADR-0009）もゴールデン（モックの出力）との一致で正しさを確かめてきた。
SysML v2 仕様との照合（[対応表](../reference/sysml-conformance.md)）で、モックの解析器に次の誤りが見つかった。

- 正しい SysML の宣言が、黙ってモデルから消える（前置メタデータ `#M`、引用名 `'…'`、引用なしの短い名前 `<R1>`）
- 部分集合 `:>`・再定義 `:>>` を型と取り違え、誤った警告を出す
- 知らない文を、何も知らせずに捨てる

モックに合わせ続けると、これらを直せない。

## 決定

- **基準の優先順位は「SysML v2 仕様 > モック」とする。** モックは、画面の操作と、仕様が決めていない表示の基準として残す。
- 仕様に合わせてモックと違う振る舞いにするときは、次のようにする。
  - 期待する結果を、仕様の根拠（BNF の規則名・章番号）とともにテストに手で書く（`web/src/core/spec.test.ts`）。モックから生成しない。
  - ゴールデンは、モックと同じ振る舞いの範囲の回帰テストとして残す。既存のケースの結果が変わる修正は、ゴールデンを手で直さず、この ADR に従って理由をテストに残す。
- Rust コア（BNF に沿った解析器）でも、同じ仕様のケースを満たす。
- 直した項目は、[対応表](../reference/sysml-conformance.md) を更新する。

## 結果

- 正しい SysML を書いた利用者に、要素が消える・誤った警告が出る、といった不具合を見せずに済む。
- 仕様のケースが増えるほど、Rust コアに移るときの基準も厚くなる。
- モックとの一致だけでは正しさを確かめられなくなる。仕様のケースを書くときは、根拠の章・規則を必ず示す。
