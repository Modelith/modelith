# ADR-0017: ほかのウェブアプリと連携する（埋め込みと図のデータの受け渡し）

- 状態: 提案
- 日付: 2026-10-16

## 背景

利用者から、次のような使い方の要望があった。

1. 別のウェブポータルで、人が自然言語で要求や構成を入力する
2. ポータルが自然言語を SysML v2 のテキストに変換する（ポータル側の領分）
3. Modelith がそのテキストから図を作る
4. ポータルが図のデータを受け取り、自分の画面に出す

今の Modelith を、この流れに当てはめて見直した。足りないところは次のとおり。

| 観点 | 今の状態 | 足りないもの |
| --- | --- | --- |
| 入口 | テキストは、手元のフォルダ・読み込んだファイル・サンプルからしか開けない（ADR-0010） | ほかのアプリからテキストを渡す口 |
| 図を作る処理 | 自動配置（`web/src/app/geometry.ts`）と SVG（`web/src/app/svg.ts`）は TS にあり、画面の状態（`S`）を通して動く。CLI の `export` は未実装、サーバは無い | 画面を介さずに図を作る口 |
| 出口 | SVG・draw.io は、利用者がメニューから選んでダウンロードするだけ（F-EXP-1・2） | ほかのアプリへ図のデータを返す口 |
| 契約 | plugin-sdk にはマニフェストと `TextEdit` しかない（ADR-0004） | ほかのアプリとやり取りするメッセージと、図のデータの形 |
| 誤りの戻し方 | 構文エラー・まだ扱えない構文は、Modelith の問題一覧に出るだけ | ポータルの変換器が直せるよう、問題を行・列つきで返すこと |
| 制約 | 利用者のモデルを、利用者が選んだ保存先以外に送らない（C-2）。サーバを持たずに静的に配信する（C-4） | 埋め込んだ親のアプリにデータを返すことを、C-2 と両立させる決まり |
| ライセンス | 本体は AGPL（ADR-0006） | ポータルが Modelith のコードを自分のアプリに組み込むと、ポータルも AGPL の義務を負う。プロセス・オリジンの境界越しにつなぐ形が要る |

自然言語から作ったテキストには、配置情報が無い。また、Modelith がまだ扱えない構文が含まれることがある。そのため、自動配置の品質と、問題を返す仕組みの重みが大きい。

## 検討した方式

| 方式 | 概要 | 長所 | 短所 |
| --- | --- | --- | --- |
| A. 埋め込み（iframe ＋ `postMessage`） | ポータルが Modelith の埋め込み用ページを iframe で開き、テキストを送る。Modelith が図を描き、図のデータ・問題・利用者が直したテキストを返す | 静的配信のまま（C-4）。描画は今のアプリと同じ。利用者がその場で図を直せる。オリジンの境界越しなので、ライセンスの影響がポータルに及ばない | ブラウザが要る。サーバだけで一括処理する用途には向かない |
| B. ヘッドレス（CLI・サーバの API） | `modelith render` や HTTP の API で、テキストから SVG・図の JSON を返す | ブラウザが要らない。一括処理・サーバ間の連携に向く | 自動配置と描画を Rust に移す大きな作業が要る。サーバは C-4 と別の配信形態になる |
| C. リンクで渡す | `…/modelith/#text=<圧縮したテキスト>` のリンクで Modelith を開く | とても簡単。URL の `#` 以降は配信元に送られない（C-2 と両立） | 一方通行で、図のデータは返らない。長いモデルは URL に収まらない |
| D. 描画部品をポータルに組み込む | npm パッケージなどで、描画のコードをポータルに入れる | 通信が要らない | ポータルが AGPL の派生物になりうる（ADR-0006）。勧めない |

## 決定（案）

### 1. 段階

| 段階 | 内容 |
| --- | --- |
| 1 | A（埋め込み）と C（リンク）を入れる。図のデータの形と、メッセージの契約を決める |
| 2 | B（ヘッドレス）。自動配置と描画を Rust に移してから、CLI の `render` を足す。サーバの API は、必要になった時点で別の ADR にする |

### 2. 埋め込みのメッセージ

ADR-0016 の手順 C で作る Worker のメッセージ（LSP と同じ考え方、版つき）に合わせる。ポータルは、Worker の外にいる「もう 1 つの利用者」として扱う。

| ポータル → Modelith | Modelith → ポータル |
| --- | --- |
| `load { version, text, layout?, view? }`：テキスト（と任意の配置・表示する図）を渡す | `ready { protocol, modelith }`：受け取れる状態になった |
| `request { version, what: "svg" \| "diagram" \| "drawio", view? }`：図のデータを求める | `analyzed { version, problems }`：問題（行・列・種類・文） |
| | `diagram { version, view, svg?, diagram?, drawio? }`：図のデータ |
| | `changed { version, text, layout }`：利用者が埋め込みの中でテキスト・図を直した |

- `version` は、ポータルが渡したテキストの版。古い版への返事は捨てる（ADR-0016 と同じ）。
- メッセージの型と JSON Schema は、`plugin-sdk`（MIT）に置く（ADR-0004）。ポータルは MIT の型だけに依存し、本体のコードを組み込まない。
- `protocol` は契約の版。plugin-sdk の MAJOR に合わせる。

### 3. 図のデータの形

- **SVG**：今の書き出し（F-EXP-1）と同じもの。ポータルがそのまま表示できる。
- **図の JSON**：要素（キー・名前・種類・位置・大きさ・ポート）と関係（ID・種類・両端・経路）。ポータルが自分で描き直す・クリックした要素をテキストの行に結び付ける、などに使う。要素のキーと関係の ID は、図の操作の意図（ADR-0016）と同じものにする。
- **draw.io**：今の書き出し（F-EXP-2）と同じもの。
- 配置は、配置ファイルの形（ADR-0005）でやり取りする。ポータルが受け取った配置を保存し、次の `load` で返せば、同じ配置で開ける。

### 4. 安全とプライバシー（C-2 との両立）

- 埋め込みのときは、親から受け取ったテキストだけを扱う。利用者のフォルダ・下書き・前回のセッションには触れず、ブラウザにも保存しない。親が受け取れるのは、自分が渡したテキストから作った図と、利用者がその場で直した結果だけになる。
- そのうえで、公開している版（GitHub Pages）は、どのオリジンからでも埋め込めるようにする。Pages では `frame-ancestors` のヘッダを付けられないため。
- 自分の環境に置く人は、配信の設定で埋め込める親のオリジンを絞れるようにする。
- 返事は、`load` を送ってきた親のオリジンにだけ送る（`postMessage` の `targetOrigin` に、そのオリジンを指定する）。
- 埋め込まれていることを画面に示す（どのサイトの中で動いているか）。
- C-2 の文言に「埋め込まれたときは、受け取ったものから作った結果を、渡した親にだけ返す」を足す。

### 5. 自動配置と問題

- 配置の無いテキストでも読める図になることを、連携の品質の目安にする。自動配置の改善は、段階 2 で Rust に移すときに合わせて行う。
- 問題は、位置（UTF-16 の位置と、行・列）と種類（エラー・まだ扱えない・トレースの抜け）をつけて返す。ポータルの変換器が、まだ扱えない構文を避けて作り直せるようにする。

## 未決（メンテナに決めてもらうこと）

- [ ] どの版で入れるか。0.1.0 は beta.1 で機能を固定する。そのため、0.2.0 で入れることを勧める（段階 1 だけを先に入れることもできる）
- [ ] 段階 1 の範囲。A・C の両方か、A だけか
- [ ] 図の JSON を、どこまで公開の契約にするか。安定するまで `protocol` を 0 のままにし、互換を約束しない案を勧める
- [ ] 公開している版を、だれでも埋め込めるようにしてよいか

## 結果（採用した場合）

- ポータルは、Modelith のコードを組み込まずに、テキストを渡して図を受け取れる。
- 静的配信のまま（C-4）。サーバを持たない人の使い方は変わらない。
- Worker のメッセージ（ADR-0016）と、埋め込みのメッセージの形がそろい、LSP・CLI・サーバでも同じ考え方で使える。
- plugin-sdk に、プラグイン以外の契約（埋め込みのメッセージ・図の JSON）が加わる。plugin-sdk の役割の説明を「Modelith とほかのソフトの契約」に広げる。
