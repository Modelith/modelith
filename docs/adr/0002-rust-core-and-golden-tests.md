# ADR-0002: Rust コアの共有とモックのゴールデン化

- 状態: 採用（モックの非公開の範囲は ADR-0009 で改訂）
- 日付: 2026-10-07

## 背景

パーサと検査ルールをブラウザ（JS）とサーバ／CI（別言語）で二重に持つと、仕様の解釈がずれる。
モックは 1 ファイル約 2,500 行の JS で、正規表現ベースの走査器で SysML v2 の一部を扱っている。

## 決定

- コア（パーサ・モデル・検査・テキスト編集）は Rust のクレート `modelith-core` として書き、
  ブラウザでは wasm、CLI・LSP・サーバではネイティブとして同じコードを使う。
- サーバも Rust（axum）とし、Go は採用しない（標準 API・MCP・サーバ側検査がモデルの解釈を要するため）。
- パーサは rust-analyzer と同じ方式（rowan 系のロスレス CST、エラー耐性あり、部分再解析可能）で作り直す。
  文法は OMG の SysML v2 / KerML 仕様の文法定義から起こす。
- JS モックは分割・リファクタせず凍結し、「動く仕様書」とする。モックは**非公開**のためリポジトリには含めず、
  メンテナの手元（`reference/mock/`、`.gitignore` 済み）にだけ置く。公開されるのはモックから生成したゴールデン JSON のみで、
  その入力（`reference/golden/cases/`）も公開してよい内容に限る。
  `reference/tools/gen-golden.mjs` がモックのパーサ・モデル構築の出力を `reference/golden/*.json` に書き出し、
  Rust 版はこれとの一致をテストで確認する（P1）。
- ゴールデンはモックの癖（不完全な構文の扱いなど）も含めて写し取る。Rust 版で意図的に挙動を変える場合は、
  差分をテスト側の許容リストに理由付きで登録する。

## 結果

- AI エージェントに移植を任せても、ゴールデンとの差分で機械的に仕様のずれを検出できる。
- モックを修正した場合はゴールデンの再生成が必要。モックを手元に置いた環境では `scripts/check.sh` が古いゴールデンを検出する。
  CI と外部の貢献者の環境ではこの検証はスキップされる。
