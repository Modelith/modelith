# ADR-0021: 複数のファイルにまたがるモデル（import と名前の解決）

- 状態: 採用
- 日付: 2026-10-22

## 背景

Modelith は、開いているファイルを 1 つずつ解析している（ADR-0015・ADR-0016）。
このため、モデルを複数のファイルに分けると、次のことが起きる。

- 別のファイルに書いた定義（部品の型・要求など）を使うと、「見つかりません」と問題一覧に出る。`import` は、どのパッケージを取り込んだかを記録するだけで、名前の解決には使っていない
- 図に、別のファイルの定義との関係（型付け・特殊化・充足・検証）が描かれない。内部ブロック図のポートも、型が別のファイルにあると出ない
- 問題を確かめるには、ファイルを 1 つずつ開くしかない

ADR-0019 は、どのファイルの集まりを 1 つのモデルとみなすかの単位として「プロジェクト」を決め、複数のファイルにまたがるモデルを 0.2.0 の候補にしていた。
メンテナの判断（2026-10-22）で、0.2.0 のアクティビティ図の次に入れる。

## 決定

### 1. モデルの単位

- **フォルダを開いているときは、そのフォルダ（プロジェクト、ADR-0019）の中の `.sysml`・`.kerml` のすべてを 1 つのモデルとする。**
- フォルダを開いていないとき（1 つだけ開いたファイル・サンプル・フォルダを開けないブラウザ、F-FILE-10）は、今までどおりそのファイルだけを 1 つのモデルとする。

### 2. 名前の解決

SysML v2（8.2.2.5）と KerML の名前の解決に従う。

- 各ファイルの一番上は、それぞれ根の名前空間とする。どの根の名前空間の一番上の要素も、ほかのファイルから**その名前で**見える（KerML の大域の名前空間）。
  たとえば、別のファイルにある `package Vehicles` は、`Vehicles::Car` や `import Vehicles::*;` で使える。
- 修飾の無い名前（`Car`）は、書いた場所から外へ向かって探し、次に `import` で取り込んだ名前を探す。ほかのファイルのパッケージの中の要素は、`import` か修飾名を使わない限り見えない。
- `import P::A;`・`import P::*;`・`import P::**;` を名前の解決に使う。`private` の要素と `private import` で取り込んだ名前は、ほかの名前空間へは見せない（可視性）。
- これまで「修飾の無い名前はファイル全体から探す」としていた割り切り（`model/names.rs`）は、同じファイルの中だけに残す。ほかのファイルへは広げない。
- 標準ライブラリの型（`ScalarValues::Real` など）の扱いは変えない。

### 3. 解析の作り

- コアに、プロジェクトのすべてのファイルを受け取り、表示中のファイルを中心に解析する入口を足す。宣言は、どのファイルのものかを持つ。
- コアの Worker（ADR-0016）は、ファイルごとの解析結果を覚えておき、変わったファイルだけを解析し直す。表示中のファイルの編集のたびに、モデルを組み直す。
- ほかのファイルは、保存したとき・ほかのアプリで変わったとき（F-FILE-8）・フォルダを読み直したときに解析し直す。
- CLI の `modelith check <フォルダ>` も同じ入口を使い、画面と同じ結果にする（ADR-0018）。

### 4. 図に出すもの

- 図には、表示中のファイルの要素と、**それが参照する**ほかのファイルの定義だけを出す（型付け・特殊化・充足・検証・メモの相手、内部ブロック図の部品の型とそのポート）。
  ほかのファイルの要素には、どのファイルのものかが分かる小さな札（ファイル名）を付ける。
- `import` で取り込んだだけで参照していない要素は、図に出さない（大きなモデルで図が混まないように）。
- 自動の図（トレーサビリティなど）も同じ考え方にする。プロジェクトのすべての要素を 1 枚に描くことはしない。

### 5. 編集

- 図や画面の操作で書き換えるのは、**表示中のファイルだけ**とする（ADR-0001 のテキスト編集は、1 つのファイルに対して作る）。
- ほかのファイルの要素を、名前の変更・削除・関係の追加などで書き換えようとしたときは、書き換えず、「この要素は ○○.sysml にあります」と知らせ、そのファイルを開く操作を示す。
- 表示中のファイルから、ほかのファイルの要素への関係（例：ほかのファイルの要求を充足する）を足すときは、表示中のファイルに書く。必要なら修飾名で書く。

### 6. 問題の一覧

- 問題一覧に、表示中のファイルだけでなく、プロジェクトのすべてのファイルの問題を、ファイルごとに並べる。行を押すと、そのファイルの該当の行を開く。
- ファイルの一覧で、エラーのあるファイル名を赤く、警告だけのファイル名を黄色くし、件数を添える。エラーのあるファイルを中に持つフォルダにも印を付ける。
- 問題の重さの選び方（F-EDIT-11）は、0.2.0 の後の項目で入れる。

## 結果

- 別のファイルの定義を使っても「見つかりません」と出なくなり、図にもその関係が出る。
- フォルダを開くと、すべてのファイルを解析するので、開いたときに少し時間がかかる。数十ファイルを目安に確かめ、大きなプロジェクトで遅いときは、別に手を打つ。
- ほかのファイルの要素を図から直接書き換えることはできない（そのファイルを開いて編集する）。複数のファイルにまたがる名前の変更は、0.3.0 以降に検討する。
- 宣言がファイルを持つようになるので、プラグインに渡すモデル（plugin-sdk の契約）にファイルを足すかは、プラグイン向けの API を整理するとき（0.3.0）に決める。
