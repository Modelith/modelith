# バージョン規則

Modelith とその関連成果物のバージョンの付け方と、各バージョンで何を約束するかを定める。
リリースの具体的な手順は [リリース手順](../development/releasing.md) を参照。

## 1. バージョンを持つもの

バージョンは次の 3 系統で独立して管理する。

| 系統 | 対象 | 表記の例 |
| --- | --- | --- |
| **アプリ** | Modelith 本体（Web アプリ・CLI・コアのクレート）。リポジトリ内のすべてで同じ番号を使う | `0.1.0` |
| **プラグイン SDK** | `modelith-plugin-protocol`（crate）と `@modelith/plugin-sdk`（npm）。両者で同じ番号を使う | `0.1.0` |
| **ファイル形式** | 図の配置ファイル（`*.layout.json`）の `formatVersion` | `1` |

- アプリと SDK は別々に番号が進む。アプリがどの範囲の SDK（プラグイン API）に対応するかはリリースノートに書く。
- `.sysml` ファイルは SysML v2 / KerML 標準のテキストであり、Modelith 独自のバージョンを持たない。

## 2. 形式

アプリと SDK は [Semantic Versioning 2.0.0](https://semver.org/lang/ja/) に従う。

```
MAJOR.MINOR.PATCH[-<段階>.<番号>]
例: 0.1.0-alpha.1 → 0.1.0-alpha.2 → 0.1.0-beta.1 → 0.1.0-rc.1 → 0.1.0
```

| 部分 | 上げるとき |
| --- | --- |
| MAJOR | 公開 API に互換性のない変更をするとき（1.0.0 以降） |
| MINOR | 機能を追加するとき。1.0.0 未満では互換性のない変更もここで行う |
| PATCH | 互換性を保った不具合の修正のみ |
| `-<段階>.<番号>` | 正式版の前の段階（下表）。番号は 1 から始め、同じ段階で出し直すたびに 1 ずつ上げる |

SemVer の規則により `alpha < beta < rc < 正式版` の順に新しいと判定される。

## 3. リリースの段階

| 段階 | 意味 | 対象 | ファイル形式・API | 次の段階へ進む条件 |
| --- | --- | --- | --- | --- |
| **alpha** | 機能を作っている途中 | 開発者自身 | 予告なく変わりうる | そのマイルストーンの機能がそろう |
| **beta** | 機能を固定し、不具合の修正のみを行う | 試用者 | 原則固定。変える場合は移行手段を用意する | 重大な既知の不具合がない |
| **rc** | 正式版の候補。致命的な不具合だけを直す | 試用者全員 | 固定 | 一定期間（目安 1 週間）重大な報告がない |
| **正式版（GA）** | 段階の接尾辞を持たないリリース | 全員 | 固定 | — |

- 正式版は、最後の rc と同じコミットに付ける。
- 1 つのマイルストーンで、すべての段階を通る必要はない（小さな PATCH リリースは rc を経ずに正式版にしてよい）。

## 4. 1.0.0 未満の扱い

- 1.0.0 未満は開発段階であり、MINOR の更新で互換性のない変更をしてよい。その場合はリリースノートに **破壊的変更** として明記する。
- マイルストーンごとに MINOR を 1 つ上げる（最初のマイルストーン = `0.1.0`）。
- 次の条件がそろったときに 1.0.0 とする。
  - 図の配置ファイルの形式を互換性を保って運用できる
  - プラグイン API を互換性を保って運用できる
  - CLI のコマンドと終了コードを互換性を保って運用できる

## 5. 互換性の対象（公開 API）

バージョン番号が互換性を約束するのは次のものだけ。これ以外（Web アプリの内部 API、wasm の関数、クレートの非公開モジュールなど）は予告なく変わる。

| 対象 | 約束すること |
| --- | --- |
| `.sysml` ファイル | Modelith が保存しても、編集していない部分の書式とコメントを変えない |
| 図の配置ファイル | `formatVersion` が同じ間は互換。上げるときは旧形式を自動で移行する |
| プラグイン API（SDK） | 下記「プラグイン API のバージョン」 |
| CLI | コマンド名・オプション・終了コード（CLI の提供開始以降） |

### プラグイン API のバージョン

- プラグインのマニフェストに書く `apiVersion` は、SDK の MAJOR と同じ値（整数の文字列）にする。
- SDK が 1.0.0 未満の間は `apiVersion` を `"0"` とし、**互換性を約束しない**（SDK の MINOR 更新で変わりうる）。
- SDK 1.0.0 以降は、`apiVersion` が同じ間は互換を保つ。

## 6. 非推奨と削除（1.0.0 以降）

- 機能や API を削除する前に、少なくとも 1 つの MINOR リリースで非推奨（deprecated）と告知する。
- 削除は次の MAJOR リリースで行う。

## 7. サポート

- 1.0.0 未満は最新のリリースだけを修正の対象とする。
- 1.0.0 以降の方針は 1.0.0 のときに定める。

## 8. タグとリリースノート

| 項目 | 規則 |
| --- | --- |
| Git タグ | `v` + バージョン（例: `v0.1.0-alpha.1`）。SDK のリポジトリでも同じ形式 |
| GitHub Release | alpha・beta・rc は「プレリリース」として公開する |
| リリースノート | Conventional Commits のコミット履歴から生成し、破壊的変更・新機能・修正に分けて書く |
