# 画面の言葉の手引き

トースト・ダイアログ・空の図の案内・メニュー・ツールチップ・問題一覧の文言を書くときの決まり。
理由は [ADR-0014](../adr/0014-plain-words-for-users.md)。利用者は SysML v2 の構文を覚えていない、と考えて書く。

## 決まり

1. **何が起きたかを、図の言葉で書く。** 「`satisfy B by A` を追加しました」ではなく「『A が B を満たす』を追加しました」。
2. **次の操作は、画面の操作で示す。** 「`expose P::*;` と書きます」ではなく、どのボタン・メニューを使えばよいかを書く。画面でできないことは、できないと書き、テキストの書き方は補足に回す。
3. **SysML v2 の用語は補足にする。** 括弧書き（「部品定義（part def）」）か、ツールチップに入れる。
4. **問題一覧は、意味を先に書く。** 原因になった書き方は、最後の括弧に書いてよい（「『満たす』関係の相手『X』が見つかりません（satisfy）」）。
5. **図の記号はそのまま使う。** `«part def»` などのステレオタイプは、SysML v2 のグラフィカル記法そのもの。
6. **ファイルの仕組みは、利用者に見える形で書く。** 「配置ファイル（.layout.json）」より「図の配置（要素の位置）」を先に書く。
7. **短く、言い切る。** 1 つの文で 1 つのことを書く。敬語は「です・ます」にそろえる。
8. **SysML の用語以外は、一般的なソフトウェアの言葉を使う（和語に言い換えない）。** 言い換えるのは、SysML v2 を知らない人が戸惑う用語だけ。
   「バージョン」「エラー」「コピー」「有効」のような言葉は、利用者がほかのソフトウェアで見慣れているので、言い換えるとかえって読みにくい。
   文も、ふつうのソフトウェアの画面として自然な語順と動詞（追加する・削除する・有効にする・読み込む・保存する）で書く。
9. **図の種類は、広く知られた図の名前で呼ぶ。** 内部ブロック図・シーケンス図・状態遷移図・アクティビティ図のように、SysML v1 や UML で定着した名前があれば、それを使う（「アクションの流れ」のような言い換えにしない）。
   SysML v2 の標準ビューの名前（ActionFlowView など）は補足にする。図の種類のツールチップに「アクティビティ図（SysML v2 では ActionFlowView）」のように添え、
   ホバーの無い狭い画面では、＋メニューの項目の下に小さく書く。Modelith 独自の図（トレーサビリティなど）は「SysML v2 では GeneralView で描く図」と書く。

## 言葉の対応

### SysML v2 の用語

画面では左の言葉を使う。種類の名前は `web/src/app/labels.ts` にまとめてあり、画面はそこから引く。

| 画面の言葉 | SysML v2（補足に書く） |
| --- | --- |
| 部品定義・部品 | part def・part |
| 要求 | requirement def・requirement |
| 関心事 | concern def |
| 検証 | verification def |
| シナリオ | occurrence def |
| パッケージ | package |
| 保存された図 | view |
| 図に出す要素 | expose |
| 絞り込み | filter |
| 満たす・検証する・扱う・導出・流れ | satisfy・verify・frame・derivation・flow |
| 依存する | dependency |
| 接続・3 つ以上をつなぐ接続 | connection・connect（n 項の `connect (a, b, c)`） |
| 結び付け（値を等しくする） | binding・bind |
| 割り当て・割り当てる | allocation・allocate |
| 流れの定義・流れ | flow def・flow |
| 定義を引き継ぐ（特殊化）・一部になる（部分集合）・置き換える（再定義）・参照する | specializes・subsets・redefines・references（`:>`・`:>>`・`::>`） |
| 一般ビュー・内部ブロック図・状態遷移図・シーケンス図・アクティビティ図 | GeneralView・InterconnectionView・StateTransitionView・SequenceView・ActionFlowView |
| ジオメトリビュー・グリッドビュー・ブラウザビュー | GeometryView・GridView・BrowserView |
| ブロック定義図（自動の図） | GeneralView で描く図（SysML v1 の bdd に当たる） |
| 順序・順序付きの流れ | succession・succession flow（`first a then b`・`then b`） |
| 開始・終了 | start・done |
| 分岐（並行）・合流（並行）・分岐（条件）・合流（条件） | fork・join・decide・merge |
| 送信・受信・代入・打ち切り | send・accept・assign・terminate |
| 条件付きの実行・繰り返し・要素ごとの繰り返し | if・while（loop）・for |
| メモ・メモを付ける相手 | comment・about（Comment） |
| 別の言語での表し方 | rep・language（TextualRepresentation） |

### 一般の言葉

SysML v2 の用語でない言葉は、左の言い換えを使わず、右の一般的なソフトウェアの言葉を使う（決まり 8）。

| 使わない | 使う |
| --- | --- |
| 版 0.1.0 | バージョン 0.1.0 |
| 誤り・誤りあり | エラー・エラーあり |
| 注意（重大度。問題一覧・CLI） | 警告 |
| 写す | コピーする |
| 設定に書き加える | 設定に登録する |
| 使う（チェックボックス）・使える（状態） | 有効 |
| 止める・止めている | 無効にする・無効 |
| 入っていない | 未追加（文では「追加されていません」） |
| 知らない項目 | 不明な項目 |
| 読み取れません | 読み込めません |
| モデルの入れ物（package） | パッケージ（package） |
| 検査ルール | チェックルール |

テストやスクリーンショットに出す名前も、実際にありそうな名前にする（プロジェクト「給水システム」、プラグイン「トレーサビリティのチェック」など）。
