# 画面の言葉の手引き

トースト・ダイアログ・空の図の案内・メニュー・ツールチップ・問題一覧の文言を書くときの決まり。
理由は [ADR-0014](../adr/0014-plain-words-for-users.md)。利用者は SysML v2 の構文を覚えていない、と考えて書く。

## 決まり

1. **何が起きたかを、図の言葉で書く。** 「`satisfy B by A` を追加しました」ではなく「『A が B を満たす』を追加しました」。
2. **次の操作は、画面の操作で示す。** 「`expose P::*;` と書きます」ではなく、どのボタン・メニューを使えばよいかを書く。画面でできないことは、できないと書き、テキストの書き方は補足に回す。
3. **SysML v2 の用語は補足にする。** 括弧書き（「部品定義（part def）」）か、ツールチップに入れる。
4. **問題一覧は、意味を先に書く。** 原因になった書き方は、最後の括弧に書いてよい（「『満たす』関係の相手『X』が見つかりません（satisfy）」）。
5. **図の記号はそのまま使う。** `«part def»` などのステレオタイプは、SysML v2 のグラフィカル記法そのもの。
6. **ファイルの仕組みは、利用者に見える形で書く。** 「配置ファイル（.layout.json）」より「図の配置（要素の位置）」を先に書く。
7. **短く、言い切る。** 1 つの文で 1 つのことを書く。敬語は「です・ます」にそろえる。

## 言葉の対応

画面では左の言葉を使う。種類の名前は `web/src/app/labels.ts` にまとめてあり、画面はそこから引く。

| 画面の言葉 | SysML v2（補足に書く） |
| --- | --- |
| 部品定義・部品 | part def・part |
| 要求 | requirement def・requirement |
| 関心事 | concern def |
| 検証 | verification def |
| シナリオ | occurrence def |
| モデルの入れ物 | package |
| 保存された図 | view |
| 図に出す要素 | expose |
| 絞り込み | filter |
| 満たす・検証する・扱う・導出・流れ | satisfy・verify・frame・derivation・flow |
| 一般の図・内部ブロック図・状態遷移の図・シーケンス図 | GeneralView・InterconnectionView・StateTransitionView・SequenceView |
