# リリース計画（0.1.0）

最初のマイルストーン `0.1.0` までの進め方。バージョンの付け方は [バージョン規則](../reference/versioning.md)、
手順は [リリース手順](releasing.md) を参照。

## 目標

モックの機能（テキストと図の同期編集、7 種類のビュー）を新しい構成で提供し、テストユーザーに使ってもらいながら育てる。

| 項目 | 決定 |
| --- | --- |
| 公開先 | GitHub Pages（`https://modelith.github.io/modelith/`）。サーバを持たず、データは利用者の手元か、利用者自身のクラウドに置く |
| 独自ドメイン | 持たない。モデルは利用者がファイルとして保存するため、将来 URL が変わっても移行できる。org の Pages には第三者が書いた HTML を置かない（保存領域を共有するため） |
| 配布形態 | Web アプリ。デスクトップアプリ（Tauri）は beta 前後に要否を判断する |
| フィードバック | GitHub Issues（不具合・要望のテンプレート） |
| スプリント | 1 週間。各スプリントの終わりに alpha を 1 つ出す |

## beta.2・beta.3 の内容

beta.1 の公開後（2026-10-21）に、機能の過不足とセキュリティを見直した（メンテナの判断）。新しい機能は足さず、
「黙って失われる」「黙って止まる」経路と、守りの不足だけを直す。いずれも振る舞いの変更なので、要求を先に更新し、テストを `verify` で結ぶ。

### `0.1.0-beta.2`：黙って失われない・黙って止まらない

| 項目 | 今の振る舞い | 直し方 |
| --- | --- | --- |
| 自動保存の失敗を知らせる | `autosave.ts` の `save` に catch が無く、フォルダの許可が切れた・ディスクが足りないときに黙って失敗する。`unhandledrejection` の受け口も無い | 失敗をトーストで知らせ、● を残す。`main.ts` に未処理の例外の受け口を 1 つ置き、トーストにする |
| 下書きの保存失敗を知らせる | `store.set` が容量超過（QuotaExceededError）を握りつぶし、「このブラウザに下書き保存されます」が嘘になる | 容量超過を 1 回トーストで知らせ、閉じる前の警告の対象に含める |
| コアの Worker が落ちた・応答しないときの出口 | `error` の監視は起動時だけ、返事の期限も無い。Worker が終了すると `opsIdle()` が解けず、保存まで黙って止まる | `error`/`messageerror` と編集の返事の期限で待ちを解き、「図の操作をやめました。テキストはそのまま残っています」と知らせる。保存は続ける。wasm が例外を返したら Worker を作り直す |
| 保存したタブの検証 | `modelith-tabs-v1` を検証せずに使い、壊れていると起動が毎回止まる（前回の続き・下書き・許可の記録は検証している） | 形を検証して不正な項目を捨てる。起動の各段を try で囲み、失敗したら「保存した設定を初期化して読み直す」を出す |
| 本体の Content-Security-Policy | `index.html` に CSP が無い（プラグインの隔離ページにはある）。将来のエスケープ漏れ 1 つがそのままスクリプト実行になる | `default-src 'self'` を基本にした CSP を `<meta>` で入れ、e2e で動作を確かめる（C-2 の機械的な裏付けにもなる） |
| プラグインのメッセージの上限 | 件数・大きさの上限が無く、洪水や巨大な 1 件で画面が固まる。診断の件数・通知の頻度にも上限が無い | 入口で大きさと待ち行列の長さを制限し、超えたら捨てて知らせる。診断の件数と通知の頻度にも上限を置く |
| 止まらないプラグインの知らせ | コマンド・取り込み・書き出しに期限が無く、無限ループしても「実行中」のまま | 期限（30 秒程度）を付け、「終わりません。停止しますか」を出す。起動の `ready` にも期限を付ける |
| 小さな守りの不足 | `createFile` だけパスの検査（`segmentsOf`）を通さない。`.layout.json` は競合を検出せず上書きする。書き出しのファイル名の拡張子を宣言に合わせない。CLI がプラグインのファイルのシンボリックリンクをたどる。wasm の断りの JSON を手書きで組み立てている | それぞれ既存の検査・仕組みにそろえる |
| 隔離のテストを Firefox・WebKit でも回す | 見直しの報告では Chromium だけとされたが、確かめると `playwright.config.ts` の projects で隔離の 3 ケースを Firefox・WebKit でも回していた | 既に実現。CSP を入れたときに WebKit で落ちたのをこのテストが捉えた（`font-src data:`） |
| CI の供給経路 | GitHub Actions をメジャータグで参照している。`cargo audit` を回していない | SHA で固定して Dependabot で更新する。`cargo audit` を check に足す |

| 項目 | 今の振る舞い | 直し方 |
| --- | --- | --- |

## beta.4 の内容

beta.3 の時点では、メニュー（ファイル・ヘルプ）・戻る・進むのボタン・パネルの切り替えが、すべて画面の右上に集まっていた。
多くのアプリは左上にメニューを置くので、利用者が操作を探しにくい（メンテナの判断、2026-10-21）。新しい操作は足さず、今ある操作の置き場所だけを変える。

| 置き場所 | 中身 |
| --- | --- |
| 左 | ロゴ、メニュー（ファイル・編集・表示・図・プラグイン・ヘルプ）、元に戻す・やり直すのボタン |
| 右 | 同期の状態、開発段階の札 |
| 狭い画面 | メニューを左の ☰ にまとめる。ツリー・図・テキストの切り替えは今のまま右に置く |

| メニュー | 項目（今ある操作を集める） |
| --- | --- |
| ファイル | 新しいファイル・ファイルを開く・フォルダを開く・保存・名前を付けて保存・自動保存・サンプルを開く・起動時にサンプルを開く |
| 編集 | 元に戻す・やり直す・すべて選択 |
| 表示 | ツリー・テキストのパネル、拡大・縮小・全体を表示・全体図 |
| 図 | 図を保存・線の描き方・整列、図を SVG で保存・draw.io 形式で書き出す |
| プラグイン | プラグインの一覧と、プラグインが足したコマンド・取り込み・書き出し |
| ヘルプ | 今のまま |

図の書き出しの強化（PNG・JPEG・`.drawio` ファイル・範囲と倍率の指定・画像のコピー）は新しい機能なので、0.1.0 の後（0.2.0）に入れる。

## beta.5 の内容

beta.4 では、図の SVG と draw.io の出力が「図」メニューに別々の項目として並び、draw.io は XML をコピーして貼り付ける画面だった。
多くのアプリは「ファイル → エクスポート」で名前と形式を選んでファイルにする。呼び方も、ほかの汎用ツールに合わせる（メンテナの判断、2026-10-22）。

| 項目 | 内容 |
| --- | --- |
| エクスポートの画面 | 「図」メニューの「図を SVG で保存」「draw.io 形式で書き出す…」をやめ、「ファイル」メニューに「エクスポート…」を 1 つ置く。ファイル名と形式（SVG 画像・draw.io）を選び、ファイルとしてダウンロードする。draw.io は `.drawio` のファイルにする |
| 言葉 | 画面の「書き出し・書き出す」を「エクスポート」、「取り込み・取り込む」を「インポート」にそろえる（[画面の言葉の手引き](ui-writing.md)） |
| 新しい図を作成 | 「図を保存…」は、名前の付いた図（view）をモデルに作る操作で、ファイルの保存ではない。ほかの SysML のツール（Create Diagram）に合わせて「新しい図を作成…」と呼び、「保存された図」を「作成した図」と呼ぶ。＋メニューは「自動で描く図」と「作成した図」の見出しに分ける。動きは変えない |
| ヘッダー | ロゴの横の副題（「— SysML v2 双方向エディタ」）を消した（#141） |
| 線の形 | 線の形（直角・曲線）は図の見た目の設定で、モデルは変わらない。「図」メニューの「線を曲線で描く」をやめ、「表示」メニューの「線の形」の小見出しの下で「直角」「曲線」から選ぶ。図のツールバーの「線：直角／線：曲線」は今のまま |

0.2.0 では、エクスポートの強化（PNG・JPEG・範囲・倍率・画像のコピー）を同じ画面に足す。

## SysML v2 の文法への対応

[対応表](../reference/sysml-conformance.md)（2026-10-20 に Rust のコアで照合し直した）の ×・△・⚠ を、次の順に埋める。項目ごとの予定は対応表の「予定」の列に書く。

| リリース | 内容 |
| --- | --- |
| `0.1.0-alpha.7` | 誤った表示（⚠）をなくす：`rep`、`assert not constraint`・`assume constraint`、パッケージ直下の `verify`、`viewpoint` の中の `frame`、同じファイルの中の `alias` と修飾名（パッケージの階層をたどる）。まだ扱えない構文の `{ }` の中身が外に漏れないようにする。読める構文を増やす：`case`・`objective`・`actor`・`include use case`・`enum` の使用・`event occurrence`・`timeslice`・`snapshot`・`typed by`・`constant`・`variant`・`rendering`・`metadata … about`・利用者定義のキーワード（`#X def`）・`by` の無い `satisfy`・`not satisfy`・`assert satisfy`・`@M` の値の式。標準ライブラリの型名の判定を直す |
| `0.1.0-alpha.8` | 構造の関係を図に描く：特殊化・部分集合・再定義・参照の線、多重度、`:=` と `default` の区別、`dependency` の線、`comment … about`・`rep` の本文、単独の `connect`・n 項の `connect`・`bind`・`binding`、`allocation`・`allocate`、`flow def`・名前付きのフロー。GeneralView・InterconnectionView の不足を埋める |
| `0.1.0-alpha.9` | 振る舞いの流れを描く：継起（`first … then`・`succession`・`succession flow`）、`fork`・`join`・`merge`・`decide`、`send`・`accept`・`assign`・`terminate`、`if`・`while`・`for`、ActionFlowView。状態の `entry`・`do`・`exit`・`parallel`、遷移の線と省略形、StateTransitionView・SequenceView の不足。`render` の合成形、`filter` の論理式、3 段以上の特徴量の連鎖 |
| `0.1.0-alpha.10` | 誤った表示（⚠）をなくす：本体が `true`・`false`・`not` で始まる制約と計算、定義の中の型の無い部品を端にする線、`satisfy requirement r : R by x`・`verify requirement r : R` と `view def` の中の `satisfy`、`@M { :>> x = 1; }`、KerML の宣言の本体の漏れ、`crosses`（`=>`）、キーワードの無い特性（`x : Real;`）と型の無い `ref`、`flow of p : T` の運ぶもの、本体付きの式（`->collect{ … }`）、関係の本体の `doc`、`'~Pt'` の共役ポート。黙って捨てる短い書き方を読む：`from` の無い `flow`・`succession flow`、`message a to b`、`connect` の無い `interface`、参照の形の `perform x.y;`・`exhibit s;`・`frame c;` |
| `0.2.0` | パッケージやファイルをまたぐ名前の解決：`import`（フィルタ付きを含む）・別のファイルの `alias`・修飾名・可視性、`expose` で import を通した名前。「複数のファイルにまたがるモデル」（ADR-0019）とあわせて行う |
| `0.3.0` 以降 | 新しい仕組みが要るもの：式の文法と評価・単位（`filter` のメタデータの値の比較を含む）、KerML の文法、標準ライブラリの同梱、GeometryView・GridView・BrowserView、`asTextualNotation`・`asElementTable`、SequenceView の複合フラグメントと入れ子のシーケンス図、ActionFlowView のパラメータとその間のフロー・区画（swim lane）、StateTransitionView の状態の使用の中の遷移と複数の状態定義、`assert constraint`・`assert not`、モデル交換（`.kpar`） |
必要になってから作る（YAGNI）。利用者の声（Issues）が無い機能は、ここに先回りして入れない。オフライン利用（PWA）も、声が出てから判断する。

## 0.1.0 より先の方向

保存と共有は、必要になったら次の順に広げる。前の段階の仕組みを、次の段階でそのまま使う。どの段階も、今は着手しない。

| 段階 | 内容 | サーバ | 判断 |
| --- | --- | --- | --- |
| 1. クラウド保存 | Google ドライブのファイルを、ローカルと同じ操作で開いて保存する | 不要 | 方式は ADR-0012（保留）。利用者の声が出てから着手する |
| 2. チームで共有 | ドライブの共有フォルダで、チームが同じモデルを開く。同時に編集したときの競合を扱う。Git・GitHub での共有も検討する | 不要 | 要求と ADR を、段階 1 の利用状況を見てから書く |
| 3. Web サービス | アカウント、チームの管理、必要なら有料プラン | 必要 | C-2・C-4・ADR-0003 の見直しを伴う。利用者の反応を見て ADR で判断する |

0.2.0 では、図の操作を次のように広げる（beta.5 で作った画面と呼び方の上に足す）。

- エクスポートの強化（PNG・JPEG・範囲・倍率・画像のコピー）を、同じエクスポートの画面に足す
- 「新しい図を作成…」で名前と図の種類を選び、空の図からも作れるようにする
- モデルのツリー（サイドバー）に作成した図を並べ、開く・名前の変更・削除ができるようにする
