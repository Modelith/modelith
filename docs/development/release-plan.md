# リリース計画（0.1.0）

最初のマイルストーン `0.1.0` までの進め方。バージョンの付け方は [バージョン規則](../reference/versioning.md)、
手順は [リリース手順](releasing.md) を参照。

## 目標

モックの機能（テキストと図の同期編集、7 種類のビュー）を新しい構成で提供し、テストユーザーに使ってもらいながら育てる。

| 項目 | 決定 |
| --- | --- |
| 公開先 | GitHub Pages（`https://modelith.github.io/modelith/`）。サーバを持たず、データは利用者の手元に置く |
| 独自ドメイン | 持たない。モデルは利用者がファイルとして保存するため、将来 URL が変わっても移行できる。org の Pages には第三者が書いた HTML を置かない（保存領域を共有するため） |
| 配布形態 | Web アプリ。デスクトップアプリ（Tauri）は beta 前後に要否を判断する |
| フィードバック | GitHub Issues（不具合・要望のテンプレート） |
| スプリント | 1 週間。各スプリントの終わりに alpha を 1 つ出す |

## アプリに最初から入れるもの

- バージョン表示と alpha であることの表示（データや形式が予告なく変わる）
- 動いている版（ビルドしたコミット）のソースコードへのリンク（AGPL 第 13 条）
- フィードバック（Issues）へのリンク
- フォントは同梱して配信する（外部の CDN に利用者の情報を送らない）。ライセンスは `licenses.txt`

## スプリント

| スプリント | リリース | 内容 |
| --- | --- | --- |
| 1 | `0.1.0-alpha.1` | モックの UI とコアを TS に移植（ADR-0009）。公開サンプル、上記の表示、Pages への自動デプロイ |
| 2 | `0.1.0-alpha.2` | ローカルファイルを開く・上書き保存、配置ファイルの分離（ADR-0005）、オフライン利用（PWA） |
| 3 | `0.1.0-alpha.3` | Rust パーサ（Worker 内 wasm）。ゴールデンと一致させる |
| 4 | `0.1.0-alpha.4` | Rust のモデル構築とテキスト編集。暫定 TS コアを差し替える |
| 5 | `0.1.0-beta.1` | 暫定コアを削除し機能を固定。以降は不具合の修正のみ |
| — | `0.1.0-rc.1` → `0.1.0` | 1 週間、重大な報告がなければ正式版 |

テストユーザーの報告次第で、スプリントの内容は入れ替える。
